# Everfresh · 常新

[![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
[![PHP](https://img.shields.io/badge/PHP-7.4%2B-777bb4.svg)](https://www.php.net/)
[![Z-BlogPHP](https://img.shields.io/badge/Z--BlogPHP-1.7%2B-orange.svg)](https://www.zblogcn.com/)

> 让旧文章，看起来一直新鲜。
>
> Keep your archive looking freshly published.

一个 Z-BlogPHP 插件：把文章按天轮换到首页列表，并将列表里的发布日期显示为当天。适合内容多、更新慢的站点——让人一眼看上去，这个站每天都在发新东西。

不改主题模板，不写数据库，卸载即恢复原样。

---

## 它做什么

| 原来 | 装上之后 |
|---|---|
| 首页第一屏半年没变过，日期还是 2025 年 | 每天换上来几篇老文章，日期显示为今天 |
| 读者一进来就知道站停了 | 像刚发了 5 篇新文章 |
| 主题、模板、数据库都要改 | 零改动，装完启用就行 |

具体规则：

- 从「起始文章 ID」开始，把已发布文章按 ID 排成一条队；
- 第 0 天取前 N 篇，第 1 天取接下来 N 篇，依次往前推；
- 这 N 篇在首页显示的日期是**今天**，时刻散落在 0 点到指定小时之间，像当天陆续发出的；
- 队列走完自动从头再来（也可以在后台指定结束日期，到那天停手）。

## 特性

- **零侵入**：只挂 `Filter_Plugin_ViewList_Template`，在渲染前替换文章数组，不动主题、不改数据库。
- **轮换不重复**：游标按「实际能上的篇数」推进，一轮之内每篇恰好出现一次，不会有的文章永远轮不到、有的连着两天出现。
- **池子再大也不慢**：用 `COUNT` + `LIMIT` 只取当天需要的那十来行，2928 篇和 10 万篇的首页耗时几乎一样。
- **多语言**：简体中文 / 繁體中文 / English 三份语言包。
- **安静降级**：任何环节出问题（查询失败、模板结构异常）都只是「不生效」，不会让首页白屏。

## 安装

1. 下载本仓库，把目录名改成 `everfresh`（必须与 `plugin.xml` 里的 `<id>` 一致）；
2. 上传到 `zb_users/plugin/`，最终路径为 `zb_users/plugin/everfresh/`；
3. 后台「插件管理」找到 **常新**，点击启用；
4. 启用后点「管理」进入设置页。

> 从旧版「文章回廊」（ID `ghx_recycle`）升级：直接覆盖目录即可，插件会自动把旧设置迁移过来，不用重填。
>
> 若站点开了整页静态缓存，装好后先清一次缓存。

## 设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| 启用首页轮换 | 开启 | 关掉后首页立刻恢复真实顺序和真实日期，插件保持启用 |
| 重排方式 | 按天轮换池子 | 另一种是「只重排当前这一页」，文章不变、只换顺序 |
| 起始文章 ID | `1` | 从 ID ≥ 这个数的第一篇开始排队；删过文章会有空档，以页面上的统计为准 |
| 每天翻新篇数 | `5` | 每天往首页换上来几篇 |
| 固定保留最新 | `5` | 这几篇常驻首页，不参与轮换；两项相加等于每页篇数 |
| 列表日期 | 改写为当天 | 也可选「保持真实发布日期」，只换顺序不改时间 |
| 每日发布时段 | `12` 小时 | 当天这批文章的时刻散在 0:00–12:00 |
| 轮换起止 | 今天起，留空循环 | 起始日留空按今天算；结束日留空就一直循环 |

设置页底部会实时显示一行统计，例如：

```
候选池 2928 篇，每天翻新 10 篇，一轮约 293 天（2026-11-06 起，自动循环，不设终点）。
```

## 自动更新

插件内置了 GitHub 更新器，把仓库当分发服务器用。设置页底部有一块「GitHub 自动更新」：

- **检查更新**：比对远程最新提交与 `plugin.xml` 里的版本号，有新版会显示版本号与提交说明；
- **立即更新**：下载源码包、备份当前文件、逐个覆盖，完成后清缓存；
- **自动检查**：后台打开时按设定间隔静默查询一次（默认 6 小时，只提示不自动装）。

默认仓库已经填好 `hexoblog-web-site/Everfresh`，也可以换成你自己的 fork（填 `owner/repo` 或直接粘仓库链接都行）。

它是怎么保证不把站搞坏的：

| 风险 | 处理 |
|---|---|
| 更新到一半网络断了 | 覆盖前先整目录备份，任一文件失败立即整批回滚 |
| 仓库被换成别的东西 | 压缩包必须含 `plugin.xml` 且 `<id>` 是 `everfresh`，否则拒绝 |
| 手滑装到旧版本 | 远程版本低于当前版本一律拒绝 |
| 压缩包路径穿越 | 只允许白名单内的路径，`../`、绝对路径全部丢弃 |
| 两个后台同时点更新 | 文件锁，同一时间只跑一个 |
| 更新文件损坏 | 解压时逐个校验 CRC32 与解压后大小 |

更新只覆盖插件自身的程序文件（`include.php`、`main.php`、`plugin.xml`、`language/`、`style/`、`inc/`）。`runtime/` 永远不在白名单里，你站上的插件设置存在数据库，也不会被碰。

**前置条件**

- 插件目录可写（一般上传时就是 755）；不可写时页面会直接告诉你哪个目录需要放开权限。
- PHP 装有 curl，或至少开启了 `allow_url_fopen`。
- 服务器能访问 `api.github.com` 与 `codeload.github.com`。国内主机如果拉不动，把网络调通再用，或手动下载 Release 包覆盖。

**发布新版的流程**（给维护者）

1. 改 `plugin.xml` 里的 `<version>`（比如 2.1 → 2.2）；
2. `git push`；
3. 站点后台点「检查更新」→「立即更新」。

版本号一定要改，否则已经更新过的站点不会提示——除非它从没更新过（首次安装后第一次更新会以 commit 为准）。

## 工作原理

```
首页请求
   │
   ├─ ViewList 查出第一页文章（主题正常流程）
   │
   ├─ Filter_Plugin_ViewList_Template 触发
   │     ├─ 判断：首页第一页？是 → 继续，否 → 原样放行
   │     ├─ COUNT 候选池大小
   │     ├─ 算游标：天数 × 每天翻新数 mod 轮换段长度
   │     ├─ LIMIT 取当天那一段 ID
   │     ├─ IN 查询取回文章对象
   │     ├─ 内存里改写 PostTime（不 Save）
   │     └─ 置顶优先 + 时间倒序重排
   │
   └─ 主题照常循环输出，缩略图/摘要/分类/评论数全部不变
```

点击文章进详情页、后台列表、RSS、sitemap 里，看到的都是**真实发布时间**——改写只发生在首页列表这一次渲染中。

## 使用须知

- **只影响首页第一页**。第 2 页起是真实列表，可能出现与第 1 页重复的文章。
- **详情页日期是真实的**。读者点进去会看到原始发布日期，这一点无法隐藏（也没有去改）。
- **这是展示层的处理**。数据库一条记录都没动，停用插件即刻恢复原状。
- **请自行评估搜索引擎风险**。对长期未更新的内容频繁变更展示日期，可能被判定为「内容未更新却改动时间」。建议仅用于个人站点、内容归档站，或把它当作排版层的「今日推荐」来用。
- 侧栏的「最新文章」模块若复用同一批文章对象，日期也会跟着变成今天——通常正是想要的效果，知道边界即可。

## 环境

- Z-BlogPHP 1.7 及以上（含 1.7.x / 2.x）
- PHP 7.4 及以上（在 PHP 8.2 下开发验证）
- MySQL / SQLite / PostgreSQL（走 Z-Blog 自带的 SQL 构造器，不拼字符串）

